# `ffi/` — the C side of the runtime

The trainers hand a StableHLO module and host buffers to a lowerer through this C layer. Lean
binds to it in [`LeanMlir/IreeRuntime.lean`](../LeanMlir/IreeRuntime.lean).

| file | what it is |
|---|---|
| `pjrt_ffi.c` | the XLA/PJRT backend every quoted number trains through |
| `lowerer.c`, `lowerer.h` | picks the backend at run time (`dlopen`), so one binary serves both |
| `iree_ffi.c`, `iree_ffi.h`, `iree_lean_ffi.c` | the IREE backend, the second lowerer the VJP oracle uses |
| `f32_helpers.c` | host-side float32 buffers: init, data loading, shuffling, argmax |
| `pjrt_c_api.h` | OpenXLA's PJRT C API header, vendored |
| `pjrt_compile_options.h` | generated by `scripts/gates/gen_pjrt_compile_options.py`; do not edit |
| `test_*.c` | known-answer tests for the shim: collectives, data-parallel invoke, guards, compile checks |

Lake builds `lowerer.c`, `f32_helpers.c` and `iree_lean_ffi.c`. The PJRT shim is built by hand,
and needs a rebuild after any edit to `pjrt_ffi.c`:

```bash
gcc -fPIC -O2 -shared ffi/pjrt_ffi.c -ldl -o ffi/libpjrt_ffi.so
```

IREE needs a source build; see [`historical/IREE_BUILD.md`](../historical/IREE_BUILD.md).
