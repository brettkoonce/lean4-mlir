# Proof-quality audit: `LeanMlir/Proofs/Codegen/*` and hand-written `LeanMlir/Proofs/Certificates/*`

Scope: static reading only. I did not build or time anything. Every time estimate below is **inferred
from reading** (goal counts, term shapes, loop bounds) unless it quotes a number already in the repo.
Each one names the timing experiment that would confirm it. Generated files (gen.txt, plus
`SmoothingCPScorecard`, `SmoothingDecScorecard`, `SmoothingDecChunk*`, `SmoothingNetWitness`,
all marked `GENERATED by`) are covered only through their generators (section C).

Cheapest way to confirm the StableHLO hypotheses (a single run, about 6 min on this box; ask the user first):
`lake env lean -Dprofiler=true -Dprofiler.threshold=2000 LeanMlir/Proofs/Codegen/StableHLO.lean`.
It prints a time for each declaration and each phase (elaboration, compilation, kernel, `simp`, and
equation-lemma generation).

In total: 206 theorems, none longer than about 40 lines. There is no `decide`, no `native_decide`,
and no `rfl` on rendered strings. The file is slow because of its **definitions**, not its proofs.

### A.1 Diagnosis, in order of likely cost (confirm with the profiler)

1. **Three to five parallel 100–215-arm matches over indexed families.** These are `SHlo`'s
   auxiliary constructions (`rec`/`casesOn`/`below`/`brecOn`/`noConfusion` for 215 constructors
   whose indices are products like `N*(oc*h*w)`), the structural `den` (215 arms, compiled through
   `brecOn`), `skel` (215 arms), `toToks`, and `emitTok`. The file's own comments measure this
   scaling: L70–L90 and L1487–L1510 note that one extra arm pushed nine unrelated proofs past a 1M
   heartbeat budget, and that "fixed-index arms are not affordable at all".
2. **Every `rfl`/`simp only [den]` proof pays for the whole of `den`.** The file has 154 `rfl` proofs
   and 13 `simp only [… den …]` proofs; across the repo there are 113 `simp only [...]` sets that
   contain `den`. Each one reduces `den` on a constructor. Reducing through the `brecOn` + matcher
   touches a term with 215 alternatives. That is the per-`whnf` cost the L70 comment describes.
3. **`deriving DecidableEq` on `Raw` (L4492) and `Tok` (L5100)**, which have about 110 and 100
   constructors. The derive handler builds an n-by-n case analysis whose off-diagonal cases each
   need a `noConfusion` proof. **I found no user of either instance.** I grepped for `==`, `decide`,
   `if` and `DecidableEq` over `Raw`/`Tok` in `LeanMlir`, `tests` and `apps` and got zero hits.
   `parse_toToks` does not need it. This is likely pure cost, and an experiment should confirm it
   before relying on it.
4. **`emitTok` is one 3,078-line definition.** It has 99 do-blocks and several thousand `s!`
   interpolation holes, and each hole needs `ToString` synthesis. The code generator also compiles
   it as a single function. Lean 4.34's async elaboration runs *theorem* bodies in parallel, but a
   `def` body is elaborated and compiled on the main thread. So `den`, `skel`, `emitTok` and the
   inductives form a serial critical path of roughly 5,000 code lines. The 206 theorems probably
   overlap with it.
5. The `#eval` writers (L9472–L9582) do I/O on **every** elaboration of a root module. That includes
   three stray `/tmp/linear_*_v.mlir` files. The rendering is small (cifar8 at B=128), so this is
   probably a few seconds. The bigger problem is architectural: see A.2.

### A.2 What could move out of the root (by payoff)

Import fan-out, computed statically with a python walk over the `import` lines in `LeanMlir/`,
`tests/` and `apps/`: **241 modules import StableHLO transitively and 68 import it directly.**
Stripping comments and matching `pretty|renderModule|emitTok|toToks|skel|serializeToks|tokIO|fmt6|OptKind`
shows that only 16 `LeanMlir.Proofs` modules plus tests/apps use the *syntactic* half. **83 of the
241 need only the semantic half (`SHlo` + `den` + `den_*` + `*_faithful`).** The other 158 reach the
syntactic half mostly because *proof* modules import *renderer* modules:
`Nets/Small/LinearTrainStep` (64 downstream), `Codegen/CnnRender` (45), `Codegen/SyncBnSites` (32),
and `Foundation/DataParallelNode` (16, which uses `skel`).

Proposed split, cheapest first:

| new module | contents (current lines) | who imports it | effect |
|---|---|---|---|
| `Codegen/StableHLOArtifacts.lean` (leaf) | `*ModuleV` renderers + `#eval` writers (9269–9582), plus the chapter-specific graphs and theorems nobody else uses: `cnnBackGraph`/`_faithful` (4152–4237, which carries the 2M heartbeat option), `cifar8FwdGraph`, `cifar8BnFwdGraph`, `mobilenetv2FwdGraph` and their `_faithful` (3959–4142). Grepping `LeanMlir`/`tests`/`apps` finds **0 external references** to `backGraph`, `cnnBackGraph`, `cifar8FwdGraph`, `cifar8BnFwdGraph`, `mobilenetv2FwdGraph` | `regen_verified_mlir.sh` module list and the proofs.yml render guard only (see memory notes "regen script's module list" and "Render guard on a new artifact") | Removes about 650 lines, all file I/O, and the root's only uses of `Nets.Small.CifarCNN` (`cifarCnnForward`, `cifarCnn8Forward`, `cifarCnnBn8Forward` appear only at 3926–4060). That import can then go, so edits to CifarCNN/MnistCNN no longer rebuild 241 modules. `Nets.MobileNet.MobileNetV2` stays, because `den` uses `relu6`/`relu6HasVJPAt`. Moving `relu6` down to an `Architectures` file would free that one too. |
| `Codegen/StableHLOPretty.lean` | `Raw`, `skel`, `Tok`, `toToks`, 4-D helpers, `emitTok`, `serializeToks`, `pretty`, `renderModule`, `fmt6`, `OptKind` (4238–9268, about 4,270 code+comment lines) | renderers, `StableHLOParse`, `DataParallelNode`, tests | The 83 semantic-only modules stop waiting for about 4,300 lines of serial def elaboration and code generation. Emitter-only edits (bf16 emit shapes, formatting), which are frequent according to MEMORY, stop rebuilding them. Adding a *new op* still touches both halves, since the constructor lives in Core. |
| (follow-up) split graph-builders from text renderers in `CnnRender`, `LinearTrainStep`, `SyncBnSites` | the `SHlo`-valued graph defs go to a proof-side file; the `String` renderers and `#eval`s go to a leaf | — | This is what would move most of the remaining 158 importers off `StableHLOPretty`. |

Deeper, not low-hanging, and the biggest lever: **extend the `BatchableOp` descriptor pattern to
`SHlo` itself.** The file already proves the pattern works. `batchOp` carries a 44-constructor,
non-recursive `denOp` for one `SHlo` arm. Doing the same for the unary and binary leaf ops would
look like `| un {a b} (op : UnOp a b) : SHlo a → SHlo b`, `| bin … : SHlo a → SHlo b → SHlo c` and
`| operand`, with `denUn`/`denBin` non-recursive. That shrinks `den`, `skel`, `toToks` and
`parseStack` from 110–215 arms to under 10. The per-op `rfl` lemmas then unfold a small non-recursive
function instead of a 215-arm `brecOn`. Every file comment about arm-count thresholds goes away.

### A.3 Findings in StableHLO.lean

### LeanMlir/Proofs/Codegen/StableHLO.lean:91 — file floor
**Smell:** heartbeats (20× default, file-wide)
**Current:** `set_option maxHeartbeats 4000000` applies to all 206 theorems. L81–83 justify it with:
"A `set_option … in` on each proof does NOT work here: the option does not attach across the
declaration's doc comment".
**Why it breaks:** The premise is wrong when the option goes *before* the doc comment. This repo
already does that 116 times in code that compiles in CI, for example
`Training/TrainedLinearDescent.lean:281`, `Training/SgdDescentCifar.lean:85` and
`Certificates/SmoothingDecChunk2.lean:15`. The file-wide floor hides which nine proofs actually
need it. The next arm that pushes a tenth proof over will not be noticed until it passes 4M.
**Suggested:** Delete L91. Wrap each proof that fails in `count_heartbeats in` (from
`Mathlib/Util/CountHeartbeats.lean`, which is present), then paste the suggested
`set_option maxHeartbeats N in` *above* its `/-- … -/`. Better still, fix the cause (next two findings).

### LeanMlir/Proofs/Codegen/StableHLO.lean:4202 — `cnnBackGraph_faithful`
**Smell:** heartbeats (stale; now a *reduction*)
**Current:** `set_option maxHeartbeats 2000000 in theorem cnnBackGraph_faithful …`
**Why it breaks:** The file floor is 4M, so this option *lowers* the budget. The L75 comment
("keeps its own larger `2000000` bump") is out of date. The proof is
`simp only [cnnBackGraph, den, mnistCnnNoBnHasVJPAt, convReluHasVJPAt, … ]; rw [HasVJPAt.backward_unique …]; rfl`.
Its cost comes from unfolding `den` and the `HasVJPAt` structures, then closing with a defeq `rfl`.
**Suggested:** Move it to the leaf module (A.2). There is no external user. Replace `den` in the
simp set with the `@[simp]` node lemmas (`den_convBack`/`convBack_faithful`, `den_selectPos`,
`den_dotOut`, `maxPoolBack…`). The closing `rfl` then only has to match the VJP records.

### LeanMlir/Proofs/Codegen/StableHLO.lean:2858, 2864, 2869, 2875, 2967, 3074, 3108, 3183, 3201, 4229 (and 113 repo-wide)
**Smell:** fragile-simpa / compile-time (unfolding the 215-arm recursor)
**Current:** e.g. `funext j; simp only [fwdGraph, den, mnistLinear, dense]`
**Why it breaks:** `den` in a simp set makes simp use `den`'s equation lemmas and matcher over all
215 constructors. L1487–L1506 record that this is exactly what "killed nine unrelated
`simp only [… den …]` proofs" when a constructor shape was added. The proofs depend on the whole
constructor list rather than on the few nodes they mention.
**Suggested:** 125 `@[simp] den_* / *_faithful := rfl` lemmas already exist. Name them:
`simp only [fwdGraph, den_addBcast, den_dotIn, den_operand, mnistLinear, dense]`. Where a node has
no lemma yet (e.g. `bnBack`, see the next finding), add the one-line `rfl` lemma. Then run a
repo-wide replacement of `simp only [… den …]` with the node lemmas across the 31 downstream files.
This also makes the downstream proofs robust to arm additions.

### LeanMlir/Proofs/Codegen/StableHLO.lean:3254, 3705 — `bnBack_faithful`, `bnPerChannelBack_faithful`
**Smell:** undocumented-defeq
**Current:** `show bnGradInput n ε γ x (den e) i = _` / `show bnPerChannelTensor3GradInput … = _`
**Why it breaks:** This only works because `den (.bnBack …)` reduces by defeq to the helper. A
refactor of that `den` arm, such as moving it into a descriptor, changes the reduct silently.
**Suggested:** Add `@[simp] theorem den_bnBack … : den (.bnBack gN xN es ε γ x e) = bnGradInput n ε γ x (den e) := rfl`
and write `rw [den_bnBack]; exact bn_input_grad_correct …`. Do the same for the per-channel case.

### LeanMlir/Proofs/Codegen/StableHLO.lean:4492, 5100 — `Raw`, `Tok`
**Smell:** compile-time (unused derived instance on a large inductive)
**Current:** `deriving DecidableEq, Repr, Inhabited` (Raw, about 110 ctors) and `deriving DecidableEq, Repr` (Tok, about 100)
**Why it breaks:** Derived `DecidableEq` scales worse than linearly in the constructor count, and
every new op pays for it. I found no user statically.
**Suggested:** Drop `DecidableEq` from both, and `Repr` too unless a `#eval` prints a `Raw`. Keep
`Inhabited`. Measure the before/after with the profiler run above.

### LeanMlir/Proofs/Codegen/StableHLO.lean:5501 — `emitTok`
**Smell:** compile-time (single 3,607-line definition)
**Current:** one `def emitTok (B : Nat) : Tok → List String → StateM EmitS (String × List String)` with 99 arms and a `| _, st =>` catch-all.
**Why it breaks:** A whole definition is one sequential elaboration and codegen unit, so its cost
cannot overlap with anything. Every emitter edit also rebuilds everything downstream (A.2).
**Suggested:** Keep the dispatcher. Move the arm bodies into per-family top-level defs
(`emitDenseTok`, `emitConvTok`, `emitBnTok`, `emitOptTok`, `emitBatchedTok`…). Each arm becomes
`| .bnPerChannelBack g x e oc h w, r :: st => emitBnBack B g x e oc h w r st`. This bounds the
size of each declaration. Do it together with the `StableHLOPretty.lean` split.

## B. Other Codegen files

### Render modules: `maxRecDepth 4000000` (EfficientNetRender:734,837,852; MobileNetV2RenderB:589,666,696; MobileNetV4RenderB:615,1004; ResNet34RenderB:1318 (+1M at 221,275); ResNet50RenderB:498,526,1147)
**Smell:** heartbeats-class option, unexplained
**Current:** `set_option maxRecDepth 4000000 in def r50FwdChainB … : StateM EmitS R50FwdRecB := do …`.
These are unrolled `do` blocks with 16–60 `let x ← …` statements. Every statement carries a
dependently-typed placeholder such as `Vec (B*(64*q1*q1))`, and the result is a 20–30-way `++` chain.
**What needs it:** Not `decide` or `rfl`. These render files have no theorems and no string
`decide`. `git log -S` shows the value first appeared in eb4de9ff (MobileNetV2 full renderer) with
no measurement, and it was copied from there. The depth comes from elaborating one very deep term:
nested `bind` continuations, dependent `let` telescopes, and the long left-nested `HAppend` chain.
`maxRecDepth` is a limit, not a cost. Setting it to 4M is harmless for speed, but it turns a runaway
recursion into a stack overflow instead of an error. For comparison, CnnRender, ViTRenderB and
ConvNeXtRenderB manage with 4000–16000.
**Suggested:** (a) Bisect to the real need; ViT/ConvNeXt suggest about 16000. (b) The structural
fix is to drive the 16 blocks from a stage table
(`[(64,256,3,q2,false),(128,512,4,q3,true),…].foldlM`) instead of unrolling `f1 … f16`, and to
accumulate `code` in an `Array String`. That caps term depth and removes the option.

### LeanMlir/Proofs/Codegen/CnnRender.lean:1897–2268 (29 s)
**Smell:** compile-time / layering
**Current:** 40 `#eval IO.FS.writeFile "verified_mlir/…"` writers follow the 17 renderer defs.
`Nets/Small/CnnFold.lean` and `Nets/Small/CifarFold.lean` import this module, and 45 modules sit
downstream.
**Why it breaks:** Every rebuild of the CnnFold chain re-renders and rewrites 40 artifacts first.
From the file shape (no theorems, 40 full train-step renders), most of the 29 s is interpreter
rendering. That is an inference; confirm with the profiler.
**Suggested:** Move L1897–end into a leaf `CnnRenderArtifacts.lean`, and add it to
`regen_verified_mlir.sh` and the proofs.yml diff list. The same split applies to
ResNet50RenderB (40 `#eval`), ResNet34RenderB (25), EfficientNetRender (34), ViTRenderB (39),
ConvNeXtRenderB (35) and IRPrint (50). For these the payoff is smaller, because their only importers
are other render files and tests.

### LeanMlir/Proofs/Codegen/RmsPropStep.lean:147–150 — `rmsBufNext_eps_placement_at_zero`
**Smell:** undocumented-defeq
**Current:** `· show μ * buf i + g i / Real.sqrt (rmsSqNext ρ sq g i + ε) = _; rw [h, zero_add]` and the `Vanilla` twin.
**Why it breaks:** It depends on `rmsBufNext` unfolding to exactly that spelling, including

### LeanMlir/Proofs/Codegen/LambTriple.lean:101, 127
**Smell:** undocumented-defeq
**Current:** `show scalarOf (fun _ => (0 : ℝ) + gradSumSq θ) = gradSumSq θ` and

### LeanMlir/Proofs/Codegen/DropPath.lean:184 — `keepProb_last`; GradClip.lean:205–206 — `clipFactor_accum`
**Smell:** brittle-chain (short)
**Current:** `rw [keepProb, Nat.cast_sub (by omega), Nat.cast_one, mul_div_assoc, div_self hd, mul_one]`;

## C. Generated certificate modules — findings against the generators

About 5,000 s of the roughly 7,700 s build is in these modules. Their proof *shapes* fall into four
families.

### C.1 `scripts/certs/ibp_conv_scorecard.py` (L484–566), and the same template in `lipschitz_cert_pair_sdp.py:307–402`, `lipschitz_cert_pair_sdp_full.py:245–349`, `lipschitz_cert_scorecard_full.py:262–280`, and the data half of `LipschitzCertInstance.lean` (G1t_eq/G2t_eq/H1t_eq/H2t_eq, L486–730)
**Smell:** compile-time (per-entry real-number `simp`), with `try` masking
**Current (emitted):**
```
theorem cx0_eval : ∀ (o : Fin 4) (i j : Fin 8), conv2d Wc bc img0 o i j = cx0 o i j := by
  intro o i j
  fin_cases o <;> fin_cases i <;> fin_cases j <;>
    · simp [conv2d, Wc, bc, img0, cx0, Fin.sum_univ_succ]
      try norm_num
```
The data are `![…]` tables of `((p:ℝ)/q)` literals. For each image the generator emits `cx_eval`
(256 goals), `box` (2×256), `pool` (2×64) and `cert` (10). That is **about 900 full-`simp` calls
over ℝ per image-radius**. Each one unfolds `![…]` indexing and `Fin.sum_univ_succ`-expanded
3×3 conv sums, and then runs `norm_num`. `IbpConvScorecardImgsA` holds two images, so about 1,800
calls. At roughly 0.25 s each that matches the reported 470–550 s per chunk. This is an inference
from goal counts; the per-goal cost needs the profiler to confirm.
**Why it breaks / costs:** The cost is linear in tensor *entries* multiplied by the cost of
default-set `simp` on real numbers. The tensor has to be split into chunks to fit in memory, and
it runs with a file-wide `maxHeartbeats 3200000` (16×). `try norm_num` hides whether `norm_num`
is needed at all. If `simp` stops closing a goal after a Mathlib bump, `try` does not report the
change, and the failure shows up somewhere else.
**Suggested (a cheaper emitted shape; this is proof by reflection, which the repo already uses in
`Foundation/ListDot.lean`, `SmoothingPhiBounds.lean` and `SmoothingCP.lean`):**
1. The generator emits data **only** as ℚ (`List ℚ` or `Fin … → ℚ`). The ℝ tensor is *defined* as
   the cast, `Wc := fun o c i j => (WcQ o c i j : ℝ)`, so no per-tensor bridge proof is needed.
2. Hand-write once: computable `conv2dQ`/`convLoQ`/`convHiQ`/`reluQ`/`maxPool2Q`/`denseTLoQ`, and
   cast lemmas `(conv2dQ W b x : ℝ) = conv2d (↑W) (↑b) (↑x)`, all by `push_cast`
   (`Rat.cast_sum`, `Rat.cast_mul`, `Rat.cast_add`, and `Rat.cast_max` at `Mathlib/Data/Rat/Cast/Order.lean:96`).
   Add a checker `ibpCertCheckQ : … → ℚ → Fin 10 → Bool` and **one** soundness theorem
   `ibpCertCheckQ WQ … imgQ εQ c = true → CertifiedAtLinf3 net (εQ : ℝ) (↑imgQ) c`.
3. Emitted per image: `theorem cert0e8 : CertifiedAtLinf3 net ((8:ℚ)/255 : ℝ) img0 7 := ibpCert_sound (by decide +kernel)`.
   The intermediate literal tensors (`cx0`, `lo0e8`, `plo0e8`…) and their 900 equalities disappear.
   Kernel ℚ arithmetic is GMP-backed (`Nat.gcd`/`mul`/`div`). Expected cost is kernel-seconds per
   image, but a timing experiment on one image has to establish that. `SmoothingPhiBounds.lean:218–221`
   records 81 s for a much larger kernel fold, which is a useful comparison.
4. Drop `try`. Emit a deterministic closer, or no closer at all.

### C.2 `scripts/certs/lipschitz_cert_scorecard_full.py` → `LipschitzCertScorecardFullNets.lean` (862 theorems), `…FullImgsA/B`, `…IBP*`, `…Crown*`
**Smell:** compile-time (reflection applied one entry at a time)
**Current (emitted, ×512):**
```
theorem gSF_14_7 : G1SF 14 7 = ∑ j, W1SF 14 j * W1SF 7 j := by
  rw [show G1SF 14 7 = ((-13075 : ℝ)/65536) from rfl, W1SFr14, W1SFr7]
  simp only [w1rSF14, w1rSF7]
  rw [sum_getD_div w1zSF14_len w1zSF7_len ((dotZ_comm w1zSF14 w1zSF7).trans gzSF_7_14) 256 256]
  norm_num
```
It also emits 272 separate `gz*_a_b : dotZ … = … := by decide +kernel` and a `…_len` lemma per row.
**Why it costs:** The ListDot bridge is correct, but it is paid 512 times. Each entry has its own
elaboration, a `show … from rfl` on a real-number literal, and a `norm_num` on real numbers.
**Suggested:** Reflect at matrix level. Add one hand-written lemma `gram_of_dotZ_table :
(∀ a b, (gz.getD a []).getD b 0 = dotZ (w.getD a []) (w.getD b [])) → ∀ a b, G a b = ∑ j, W a j * W b j`
with `G`/`W` defined as casts of the ℤ tables over `65536`. The emitted proof becomes
`gram_of_dotZ_table (by decide +kernel)`: one kernel evaluation per matrix instead of 784 theorems.
Apply the same idea to the per-image margin/argmax blocks in `…FullImgsA` (666 theorems).

### D.2 LeanMlir/Proofs/Certificates/SmoothingCP.lean:516 — `binomTailNum`
**Smell:** compile-time (quadratic kernel work behind a "~0.1 s" claim)
**Current:**
```
def binomTailNum (N k a d : ℕ) : ℕ :=
  ∑ i ∈ Finset.range (N - k + 1),
    N.descFactorial i / i.factorial * a ^ (N - i) * (d - a) ^ i
```
**Why it costs:** The kernel accelerates `Nat.mul`/`div`/`pow`/`gcd` with GMP, but **not**
`Nat.descFactorial` or `Nat.factorial`. Those unfold one recursor step per unit of `i`, so term `i`
costs about 2i bignum steps and a tail of length T costs about T². From the scorecard's own
statements, across the 279 entries **Σ T = 205,901, max T = 4,834, and Σ T² ≈ 5.8·10⁸**. That is
consistent with most of the 392 s being a few long-tail entries. The L507 comment's "~0.1 s even
for thousands of terms" does not hold for them, since the average is 1.4 s per entry. The sibling
file already found and fixed this same "re-fold the prefix" pattern for Φ
(`SmoothingPhiBounds.lean:218–221`).
**Suggested:** An incremental running binomial, proven equal to `binomTailNum` once:
```
def binomTailNumAux (N a d : ℕ) : ℕ → ℕ → ℕ → ℕ   -- fuel i, running C(N,i), acc
  | 0,     _, _, acc => acc
  | f + 1, i, c, acc => binomTailNumAux N a d f (i + 1) (c * (N - i) / (i + 1))
                          (acc + c * a ^ (N - i) * (d - a) ^ i)
```
The division is exact by `Nat.choose_succ_right_eq` (`Mathlib/Data/Nat/Choose/Basic.lean:210`).
Prove `binomTailNumAux N a d (N-k+1) 0 1 0 = binomTailNum N k a d` by induction, and point
`binomTail_le_of_kernel_check` at the Aux form. The kernel work becomes O(T) bignum steps per entry.
The generator does not change.

## Recurring patterns (fix the pattern, fix it everywhere)

1. **Per-entry real-number `simp`/`norm_num` where one reflected check would do.** The repo already
   has the right tool (`ListDot`, `phiScanRev`, `binomTailNum`: a ℚ/ℕ/ℤ computation, one bridge
   lemma, `decide +kernel`). But several generators still emit `fin_cases … <;> simp [data, Fin.sum_univ_succ]; try norm_num`
   over `![…]` real literals (IBP-conv, pair-SDP, scorecard-full, the LipschitzCertInstance data).
   Others reflect one *entry* at a time (FullNets). Moving every generator to "data as ℚ, ℝ tensor
   defined as the cast, one soundness lemma, one `decide +kernel` per image or matrix" targets the
   roughly 5,000 s of generated-module time. Also stop emitting `try`.
2. **Recomputation inside kernel-reflected functions.** `binomTailNum` recomputes `descFactorial`
   and `factorial` for each term, which is quadratic. `SmoothingPhiBounds` already fixed the same
   shape by threading the running value. Audit every `decide +kernel` target for non-GMP recursion
   (`factorial`, `descFactorial`, `choose`, `List.range`-indexed `getD`) that is re-entered per term.
3. **Root-module bloat from large closed inductives and co-located side effects.** A 215-constructor
   `SHlo` with 215-arm `den`/`skel`, parallel 110-arm `Raw`/`Tok`/`parseStack`, unused derived
   `DecidableEq`, a single 3,600-line `emitTok`, and `#eval` artifact writers, all live in the file
   that 241 modules import. On top of that, proof modules import renderer modules
   (`LinearTrainStep` → 64, `CnnRender` → 45), and a Foundation module imports a 383 s instance
   module (`IntervalBound` → `LipschitzCertInstance`). The mainstream fixes are: split the semantic
   core from the printer and from artifact writers; keep `#eval` I/O in leaf modules or an `exe`;
   use named `@[simp]` equation lemmas instead of `simp only [den]`; and use descriptor sub-inductives
   (the file's own `BatchableOp` pattern) so the recursive `den` stays small.
